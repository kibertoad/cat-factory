A failed load no longer looks like an empty or switched-off feature. Only the module-off 503 (the
unreasoned `unavailable` envelope) now means "not enabled"; any other failure, an outage 503
included, shows a new `LoadFailedState` with a retry in the consensus,
requirements-review and brainstorm windows, the foundational-services, skill-library,
observability, release-health and environment-handler surfaces, the account deployment settings,
the observability incident tools, the board members roster (whose skeleton no longer stays up for good), the service spec window
(which now reads the anchor diagnostics), the GitHub installation list and the repo tree browser.
The add-task modal reports a failed documents, issues or fragments load, and the operator
dashboard shows its failure through the same state and says when there is no active account
instead of showing a blank body. The integrations hub keeps the observability row, with a failed
badge, when its read fails.
