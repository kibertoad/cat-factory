Add a setup checklist (Configuration → Setup checklist, or the palette) for people who can change the workspace setup. It lists every prerequisite for "a task can run and merge" (model, source control, where agents run, test environments, screenshot storage) with its state and one action per row, composed from the probes the setup banners and startup dialogs already read. A row that needs attention says why (unreachable, a missing setting, a rejected or under-scoped token, a broken default preset, or a check that did not answer), and its action opens what the matching banner opens for that cause. A row follows the banners' rule for who may act on it: someone who cannot save the fix sees who can instead of a button. A probe that has not answered shows as checking, never as missing or done, and a failed probe offers "Try again". The banners and dialogs are unchanged. The GitHub store now records why the integration is unavailable (switched off, or the probe failed). The setup banners and the checklist open each fix through one shared map (`useSetupRemedies`), so a row and its banner cannot point at different screens. A token row says whose token it is, and a missing local token says to set `GITHUB_PAT`. A backend that does not report its infrastructure gets a row that says so instead of a spinner.
